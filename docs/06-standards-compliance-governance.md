# 06 — International Standards & Compliance Governance

**Статус:** DRAFT · **Дата:** 07.11.2026.  
**Это политика работы с правилами, не правовое заключение и не разрешение на регулируемые перевозки.**

## Правило номер один

В KERUENIX существуют разные справочники: **товар**, **физическая грузовая единица**, **груз/опасность**, **таможенная классификация**, **транспорт**, **географическая точка**, **документ**, **правило**. Их нельзя объединять в единую строку `cargoClass`.

## Границы международных кодов

| Код/стандарт | Что означает | Чем не является |
|---|---|---|
| GS1 GTIN | товарная единица | ID конкретной паллеты |
| GS1 SSCC | логистическая единица, при легальном выделении | документ, таможенная декларация или право доступа |
| GS1 GLN | участник/физическая локация | ID tenant и авторизация |
| GS1 EPCIS/CBV | обмен событиями видимости груза | замена ledger склада или электронной подписи |
| ISO 6346 | контейнерная идентификация | назначение маршрута |
| UN/LOCODE | код международного транспортного местоположения | точные координаты ворот |
| WCO HS6 / ЕАЭС ТН ВЭД10 | товарная классификация | GTIN или UN опасного груза |
| UN dangerous goods + ADR/IMDG/ICAO/RID | опасность и применимые правила перевозки | универсальный порядок разрешённого соседства по одному номеру |
| CMR/eCMR | документы/договор международной автомобильной перевозки | автоматическое таможенное декларирование |
| TIR/eTIR | специальная процедура/система транзита | обязательный режим всех международных рейсов |
| ISO 780 | знаки обращения с упаковкой | опасная маркировка |
| Национальная DataMatrix маркировка | обязательная по определённым категориям продукции | универсальная грузовая SSCC-этикетка |

Если GS1 SSCC отсутствует, разрешён только **честно обозначенный KERUENIX INTERNAL LPN**, а не выдуманный SSCC. SSCC/GS1-128, опасная маркировка, таможенные документы и Data Matrix проверяются по отдельным обязательствам.

## Регуляторный RuleSet

`RegulatorySource(id, issuer, country, mode, title, version, official_url, license, effective_from, verified_at)`  
`RuleSet(id, source_version, subject, conditions, effect, reviewer, checksum, status, valid_from/to)`  
`ComplianceAssessment(id, tenant, cargo, vehicle, route, location, evidence, ruleset_version, result, timestamp)`.

Lifecycle: `DRAFT → SOURCE_VERIFIED → EXPERT_REVIEW → APPROVED → ACTIVE → SUPERSEDED/REVOKED`.  
Статусы решения: `ALLOW, ALLOW_WITH_CONTROLS, DENY, NEEDS_REVIEW`; отсутствие источника или необходимых фактов не даёт автоматического `ALLOW`.

Требования применимости: страна отправления/назначения/транзита, погранпереход, вид транспорта, дата действия, конкретный груз, упаковка, опасность, маркировка, документы, класс кузова/цистерна, массы/оси, СВХ/таможенная процедура.

## Процедура экспертного утверждения

1. **Legal/Compliance** закрепляет ссылку на официальную актуальную редакцию и применимость.
2. **Operational owner** описывает физическое исполнение: загрузку, склад, документы, охрану, таможню.
3. **Security/Architect** проверяет data/tenant/evidence permissions.
4. **QA** создаёт positive/negative/gap тесты, включая «неизвестно» и запрещённые сочетания.
5. **Dual approval** на DG/customs/правила выпуска, version pin, ограниченная активация.
6. **Audit/SRE** контролирует изменения источников и затронутые будущие и действующие перевозки.
7. При проблеме — rollback с сохранением исходного decision snapshot; не переписывать историю.

Виртуальные роль-персоны из `idea/21` являются способом разработки требований; окончательное правовое подтверждение требует компетентного реального специалиста.

## Отдельные документы и внешние интеграции

Таможенный `CustomsHold` не снимается GPS, клиентским QR или неподтверждённым webhook. CMR/eCMR, TIR/eTIR, KEDEN и национальные системы имеют независимые процессные контуры и требуют официально разрешённых интерфейсов/учётных прав. **Наличие описания API в документации не является подтверждением технического подключения.**
