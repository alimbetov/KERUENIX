# KERUENIX — единая концепция проекта

**Версия:** 0.1 · **Дата:** 07.11.2026 · **Статус:** концепция для обсуждения, не утверждённое ТЗ.

## Суть идеи

KERUENIX — многоклиентская логистическая SaaS-платформа (TMS + управление автопарком + диспетчеризация + контроль исполнения + расчёт себестоимости). Компания-заказчик может оформить перевозку, а экспедитор или перевозчик — подобрать ресурсы, рассчитать выполнимый маршрут, организовать рейс и сопоставить плановые и фактические затраты.

**Основная ценность:** система оценивает последствия решения в километрах, времени, топливе, рисках и деньгах, а не только показывает местоположение автомобиля.

## Для кого

- Грузоотправитель — запрос цены, сроки, документы и прослеживаемость груза.
- Экспедитор — планирование собственных/чужих машин, коммерческая маржа и партнёры.
- Перевозчик — маршруты, рейсы, водитель, мониторинг, затраты и топливо.
- Диспетчер — контроль отклонений и обоснованное перепланирование.
- Склад/СВХ — окна прибытия, приёмка и события передачи груза.
- Администратор компании — сотрудники, роли, тарифы, биллинг и интеграции.

## Безопасная многоклиентность

**Tenant** — независимая компания/контрактная группа с собственным контуром данных. В одной системе могут работать десятки таких компаний. Разные участники одной перевозки взаимодействуют через *ограниченные разрешения на конкретную отправку*, но не получают доступ к чужим тарифам, финансовым данным и истории GPS.

Базовый вариант: PostgreSQL/PostGIS, tenant_id + RLS + проверка полномочий в приложении. Отдельные БД для крупных клиентов — возможное расширение.

## Функциональные блоки

1. Заказы, грузовые места, коммерческие предложения, бронирование.
2. Маршруты для грузового транспорта, пробки, перекрытия, ETA и время выезда.
3. Собственный/партнёрский автопарк, диспетчеризация, водители и маршрутный лист.
4. GPS, история событий, геозоны, предупреждения, подтверждение доставки.
5. Расчёт себестоимости, порожнего пробега, топлива и доходности.
6. Склады, СВХ, перегрузки, окна и таможенные статусы (по этапам).
7. Timefold для оптимизации; Tribuo для будущего прогноза, с резервным расчётом.
8. Железная дорога, море, авиация и дроны — после подтверждения первого MVP.

## Основные принципы

- Один заказ ≠ одна машина: заказ может иметь несколько партий/участков; одна машина обслуживает несколько заказов.
- Жёсткие ограничения (безопасность, допуск, вместимость) важнее экономической оптимизации.
- План, прогноз и факт храним отдельно; изменения диспетчера версионируем.
- GPS транспорта ≠ подтверждённое местоположение груза.
- Внешние карты, GPS, WMS, АЗС и ERP подключаем адаптерами.
- ML не блокирует работу: сначала проверяем алгоритмы и качество данных.
- Каждая цена и рекомендация должны быть воспроизводимыми.

## MVP

**Первый сквозной сценарий:** клиент создаёт заявку → система предлагает варианты с ценой/ETA → подтверждение → выбор транспорта → утверждение маршрута → GPS-мониторинг → доставка/доказательство → план/факт себестоимости.

**Проверочная выборка:** 2 независимые компании, 10 условных машин, 20 заказов, партнёр, склад, сценарии перекрытия, устаревшего GPS, дублирования событий и конфликта резервирования.

## Предлагаемый стек

Java 21 + согласованная версия Spring Boot, Next.js/React, PostgreSQL/PostGIS, Redis, RustFS/S3; Timefold Solver, Traccar, сменный маршрутизатор; Tribuo как позднее подключаемый Java ML-модуль. Сначала — модульный монолит, а не набор независимых микросервисов.

## Что пока не решено

Первый платящий сегмент; тарифная модель; список стран; требования по персональным данным и GPS; легальные ограничения грузовых дорог; провайдер трафика; правила межкомпанийной видимости; необходимость отдельных БД; финансовые/налоговые правила; экономическая эффективность интеграций.

Полные материалы (на английском, пригодные для ADR, задач и реализации) см. в [индексе](README.md), документы 01–12.
